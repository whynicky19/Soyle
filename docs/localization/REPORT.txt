Архитектура
Фактический frontend — Next.js 16 / React 19, backend — FastAPI. Проект не переносился на Nuxt.
Добавлены словари ru-RU и kk-KZ: 222 согласованных ключей. locale.ts содержит нормализацию,
параметры сообщений, Intl.PluralRules и форматирование дат; i18n.ts — React-подписку.
Компоненты получают обновления языка без перезагрузки. Изменение языка не перемонтирует приложение.
Переводы не запрашиваются у внешней переводческой модели. DOM-подмена текстов не используется.

Язык
Первый выбор доступен в модальном диалоге с нативной блокировкой фонового интерфейса.
Гостевой выбор хранится в localStorage (soyle-language, BCP-47).
Профиль сохраняет совместимые с существующим API коды ru / kk в user_settings.
Существующее предпочтение аккаунта имеет приоритет при входе. Если предпочтение ещё не задано,
используется гостевой выбор. В запросах API отправляется Accept-Language, в ответах Content-Language.
В детский сайдбар добавлена доступная кнопка настроек. Переключатель есть в детских настройках,
в форме входа и кабинете специалиста. При ошибке сохранения возвращается последняя сохранённая настройка.
Настройки камеры, звука, темы и спокойного режима сохраняются вместе с языком без сброса.

Переведённые части
Основные тексты авторизации и регистрации, настройки, настройки пингвина, реплики всех шести
событий питомца, часть навигации и детских экранов. Локализован текстовый вариант брендового слогана,
чтобы не показывать русскую надпись, запечённую в растровом логотипе.
Backend возвращает казахские сообщения HTTP-ошибок и ошибок валидации; это ещё не перевод всех API-данных.
Для динамических сообщений API, статистики, советов и отчётов требуется дополнительная работа.

Учебные материалы и миграция
Статический учебный словарь содержит 139 пар. Миграция 40 сохраняет исходные упражнения и
создаёт переводы, привязанные к исходному exercise_version_id. ID упражнений и ключи ответов неизменны.
Доступны статусы draft / needs_review / approved. Любая правка снимает одобрение.
Редакции сохраняются в exercise_translation_history; проверяется revision при конкурентной записи.
Редактор доступен администратору в настройках. Специалист видит отдельную панель проверки в кабинете.
Администратор не может вызвать endpoint одобрения: он доступен только роли specialist.
Публикуются только переводы со специалистом-проверяющим, причём только для auditory_choice / action_choice.
Для других механик одобрение блокируется, пока не появятся отдельные адаптеры языковой логики.
При отсутствии одобренного перевода каталог kk-KZ исключает упражнение; русский текст не подставляется
вместо перевода. Это ограничение относится к общему каталогу упражнений, а не ко всем отдельным API историй/AAC.
