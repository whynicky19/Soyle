# Söyle

Учебный MVP веб-платформы для поддерживаемой коммуникации, игровых заданий и назначенной домашней практики. Söyle объединяет ребёнка, родителя и специалиста в одной персональной программе. Публичный лендинг доступен на `/`, вход и кабинеты — на `/app`.

> Söyle не ставит диагноз и не заменяет врача или логопеда. Цели и упражнения для ребёнка необходимо согласовывать со специалистом.

## Возможности

- Регистрация родителей и серверная сессия в защищённой HttpOnly-cookie с CSRF-защитой; bearer-токен оставлен только для локальных API-тестов.
- Роли: администратор, родитель, специалист и ученик.
- Профили детей и изоляция данных родителей.
- 13 общедоступных игровых заданий: 3 задания на слух и 10 учебных AAC-сценариев. Ещё 6 моторных практик скрыты от автоматического плана и становятся доступны конкретному ребёнку только после назначения специалистом.
- Необязательное локальное зеркало камеры без распознавания изображения, биометрии, оценки движения или диагностических выводов.
- Озвучивание слов и AAC-фраз: обработанный серверный голос при доступном локальном движке и автоматический браузерный голос в Linux/Vercel.
- Запись хода занятий: однозначные игровые ответы отделены от участия, отказа, перерыва и технической ошибки. Эти данные не являются измерением речи или развития.
- Персональный план: сначала назначения специалиста, затем безопасное разнообразие немоторных заданий. Автоматический поиск «слабого навыка» отключён.
- Индивидуальные цели со сроком, критерием, сложностью и статусом.
- Занятия на 3, 5 или 10 минут: соответственно 2, 3 или 5 спокойных заданий, визуальное расписание, пауза и сохранение незавершённого занятия.
- Защита от повторного создания занятия: после перезагрузки продолжается та же сохранённая сессия.
- AAC-конструктор сообщений до восьми карточек с понятным порядком и удалением отдельных карточек.
- Открываемый профиль аккаунта и ребёнка со статистикой и текущими настройками.
- Домашние задания с пятью вариантами результата и отображением специалисту.
- Учёт самостоятельности, подсказок, времени ответа и коммуникационных инициатив.
- Админ-панель: статистика, роли, блокировка аккаунтов, добавление и архивация заданий.
- Учёт ресурсов автоматических функций: запросы, токены, модель, функция и расчётная стоимость.
- Кабинет специалиста с ручными целями, назначениями, домашней практикой и описательным отчётом. Автоматические клинические рекомендации отключены.
- Проверенный интерфейс текущего этапа — только русский. Незавершённые KK/EN скрыты до полной лингвистической, контентной и TTS-проверки.
- Четыре различимые темы: шалфей, океан, лаванда и высокий контраст.
- Ограничение попыток входа по сочетанию клиента и аккаунта, журнал критических действий, согласия, расширенный экспорт и удаление данных ребёнка через API.

## Стек

- Frontend: Next.js 16, React 19, TypeScript, Web Speech API.
- Backend: FastAPI, PostgreSQL/SQLite, Pydantic, PyJWT, Argon2.

## Как запустить локально

### Что понадобится

- macOS или Linux;
- Python 3.11 или новее;
- Node.js 20 или новее;
- `npm` и `curl`.

### Быстрый запуск фронтенда и бэкенда одной командой

Откройте терминал, перейдите в корневую папку проекта и выполните:

```bash
cd /путь/к/Soyle
./start.sh
```

При первом запуске скрипт автоматически:

1. создаст Python-окружение в `backend/.venv`;
2. установит зависимости backend и frontend;
3. запустит API и веб-приложение.

После появления сообщения `Ready` откройте:

- главная страница: http://localhost:3000;
- вход в платформу: http://localhost:3000/app;
- документация API: http://127.0.0.1:8010/docs.

Оба сервера работают, пока открыт терминал. Для остановки нажмите `Ctrl+C`.

Если macOS не разрешает выполнить скрипт, один раз выдайте ему право на запуск:

```bash
chmod +x start.sh
./start.sh
```

### Раздельный запуск фронтенда и бэкенда

Этот вариант удобен для разработки: backend и frontend будут работать в двух отдельных терминалах.

#### Терминал 1 — backend

При первом запуске выполните:

```bash
cd /путь/к/Soyle/backend
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
export SOYLE_SECRET_KEY="local-development-secret-change-me"
export SOYLE_SEED_DEMO_DATA=true
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8010
```

При следующих запусках достаточно:

```bash
cd /путь/к/Soyle/backend
source .venv/bin/activate
export SOYLE_SECRET_KEY="local-development-secret-change-me"
export SOYLE_SEED_DEMO_DATA=true
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8010
```

Backend будет доступен по адресам:

- API: http://127.0.0.1:8010;
- документация API: http://127.0.0.1:8010/docs;
- проверка состояния: http://127.0.0.1:8010/health.

#### Терминал 2 — frontend

При первом запуске выполните:

```bash
cd /путь/к/Soyle/frontend
npm install
cp .env.local.example .env.local
npm run dev
```

Если файл `frontend/.env.local` уже существует, команду `cp` выполнять не нужно.

При следующих запусках достаточно:

```bash
cd /путь/к/Soyle/frontend
npm run dev
```

Frontend откроется на http://localhost:3000 и подключится к API по адресу `http://localhost:8010`. Не смешивайте в браузерной конфигурации `localhost` и `127.0.0.1`: для cookie-сессии они считаются разными сайтами. Сначала запускайте backend, затем frontend. Каждый сервер останавливается сочетанием `Ctrl+C` в его терминале.

### Если приложение не запускается

- Убедитесь, что порты `3000` и `8010` не заняты другими программами.
- Проверьте версии командами `node --version` и `python3 --version`.
- Если страница открылась без данных, убедитесь, что API отвечает по адресу http://127.0.0.1:8010/health.
- После изменения зависимостей остановите сервер через `Ctrl+C` и снова выполните `./start.sh`.

## Автоматические тесты

```bash
cd backend
source .venv/bin/activate
pip install -r requirements-dev.txt
pytest -q
```

Тесты проверяют cookie-сессию, CSRF, выход, авторизацию и роли, изоляцию данных детей, согласия и их немедленный отзыв, ограничение попыток входа, безопасный план без неназначенной моторики, цели, домашнюю практику, паузу занятия, серверный расчёт игровых результатов, неоцениваемые исходы, AAC-грамматику и целостность фраз, экспорт/удаление, активный каталог, уведомления и языковую валидацию TTS.

Для интерфейса доступны отдельные регрессионные проверки безопасных настроек, линтер и production-сборка:

```bash
cd frontend
npm test
npm run lint
npm run build
```

## Локальные демо-аккаунты

Демо-данные создаются только при явном `SOYLE_SEED_DEMO_DATA=true`; `start.sh` выставляет этот флаг для удобного локального запуска. В production/staging включение демо-данных блокируется с ошибкой; администратор создаётся один раз из `SOYLE_ADMIN_USERNAME` и `SOYLE_ADMIN_PASSWORD`.

На чистой локальной базе доступны следующие аккаунты:

| Роль | Логин | Пароль или PIN |
|---|---|---|
| Родитель | `parent` | `Parent123!` |
| Ребёнок | `alikhan` | `1234` |
| Специалист | `specialist` | `Specialist123!` |
| Администратор | `admin` | `Admin123!` |

Для ребёнка на экране входа выберите вкладку «Ребёнок». Родитель, специалист и администратор входят через вкладку «Взрослый» — система откроет кабинет в соответствии с ролью аккаунта.

## Deployment на Vercel

Проект разворачивается как два Vercel-проекта из одного репозитория:

- `frontend` — Next.js, переменная `NEXT_PUBLIC_API_URL` указывает на адрес API;
- `backend` — FastAPI, подключённый к PostgreSQL через `DATABASE_URL`.

Обязательные переменные backend перечислены в `backend/.env.example`. В production задайте `SOYLE_ENV=production` и уникальный `SOYLE_SECRET_KEY` длиной не менее 32 байт. Локальные `.env*`, SQLite-базы и служебная папка `.vercel` исключены из Git.

Если frontend и API находятся на разных сайтах, backend дополнительно требует `SOYLE_COOKIE_SAMESITE=none`, точный `SOYLE_ALLOWED_ORIGINS` и HTTPS. Для одного сайта оставьте более строгий режим `lax`. CSRF-токен передаётся в JSON при входе и проверке текущего сеанса, хранится frontend только в памяти вкладки; JWT остаётся в HttpOnly-cookie API.

На macOS API использует системный голос `say` и `ffmpeg`. В Linux/Vercel системного `say` обычно нет, поэтому приложение автоматически переключается на Web Speech API браузера; дополнительные серверные пакеты для этого не требуются.

При запуске `init_db()` применяются совместимые добавочные изменения схемы: цели, домашняя практика, согласия, журнал действий, ограничение входа и контекст занятий. Для production перед развёртыванием всё равно необходимы проверка миграции на копии базы и план отката.

## Приватность

- Камера после отдельного согласия используется только как локальное зеркало: приложение не анализирует кадры и не отправляет их в API.
- Видео и звук не сохраняются.
- Backend хранит аккаунты, профили детей, согласия, назначения, описательные записи занятий, AAC-историю и служебный аудит.
- Для реального пилота нужны юридически проверенное согласие законного представителя, политика обработки данных, резервное копирование и проверка упражнений логопедом.
- Текущий вердикт и обязательные внешние условия зафиксированы в [`PILOT_READINESS.md`](PILOT_READINESS.md).
