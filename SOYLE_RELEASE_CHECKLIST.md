# Söyle — checklist внешнего пилота

Актуально на 12 октября 2026 года.

## Решение сейчас: NO-GO

P0, P1, P1.5 и P2.1 проверены локально, но внешнее использование с реальными детскими данными запрещено до закрытия всех обязательных блоков ниже. Автоматические тесты не заменяют методическую, юридическую, privacy, security или accessibility-экспертизу.

- [x] Исторические motor-данные и код сохранены для review.
- [x] Публичное упражнение связано с неизменяемой опубликованной версией.
- [x] Новый admin-content создаётся как `DRAFT / pending`.
- [x] Техническая валидация и preview выполняются до публикации.

- [x] Backend (34), frontend (32), TypeScript и ESLint проходят локально.
- [x] Playwright E2E локально проверяет child/parent/admin flow, аудио fallback, pause/refusal, save/reopen, DRAFT-gate, publish-gate, axe и overflow на desktop/mobile/tablet.

## 4. Privacy и consent review — обязательный blocker

- [ ] Составлена data inventory/data-flow карта от браузера до БД и внешних сервисов.
- [ ] Проверено соответствие каждого поля заявленной цели и принципу минимизации.
- [ ] Свободный AI-ввод не допускает неуправляемой передачи PII или включён только после согласованной модели.
- [ ] Отзыв каждого необязательного согласия немедленно прекращает новые операции.
- [ ] Определено, что происходит с уже сохранёнными данными после отзыва.
- [ ] AAC-history реализована как прозрачный opt-in; чувствительные свободные сообщения не записываются скрыто.
- [ ] Персональные фото/upload остаются выключенными до отдельной модели хранения, ACL, удаления и модерации.
- [ ] Экспорт и удаление проверены владельцем данных на полной схеме production-подобной БД.
- [ ] Логи, аналитика, ошибки и backup не содержат лишних детских или секретных данных.

## 5. Security review — обязательный blocker

- [ ] Проведён threat model для parent/student/admin и будущего specialist.
- [ ] Выполнен независимый review cookie, CSRF, CORS, rate limits, session revocation и password/PIN policies.
- [ ] Проверены IDOR/семейная изоляция на каждом child-scoped endpoint.
- [ ] Проверены privilege escalation и защита последнего администратора.
- [ ] Секреты отсутствуют во frontend, истории Git, логах и артефактах сборки.
- [ ] Утверждены backup encryption, key rotation, least privilege и production secret storage.
- [ ] Есть восстановление доступа и revocation active sessions.
- [ ] Dependency/container scan не содержит неразобранных critical/high уязвимостей.
- [ ] Specialist-role остаётся feature-closed до новой ACL-модели и отдельного security review.

## 10. План контролируемого пилота — обязательный blocker

- [ ] Утверждены цель пилота, критерии включения/исключения и недиагностические outcome measures.
- [ ] Определены небольшой scope функций и версия каталога; неподтверждённые функции закрыты feature flags.
- [ ] Получены требуемые согласия и этические/организационные approvals.
- [ ] Определены обучение семей, канал поддержки и процедура досрочного прекращения участия.
- [ ] Определены критерии немедленной остановки пилота и ответственные лица.
- [ ] Согласован порядок сообщения о дискомфорте, ошибке контента, privacy/security incident.
- [ ] Зафиксировано, что доступ к AAC, помощь и отказ не зависят от выполнения упражнения.
- [ ] После пилота предусмотрены качественный разбор, удаление/хранение данных по утверждённым правилам и отдельное решение о следующем релизе.

## Финальный release gate

Внешний пилот может получить `GO` только после:

1. закрытия всех обязательных пунктов разделов 2–10 с именем ответственного и ссылкой на доказательство;
2. повторного полного тестового прогона на release candidate;
3. письменного sign-off владельца продукта, методиста, legal/privacy и security;
4. отдельного решения о deployment — сам этот checklist deployment не разрешает.
